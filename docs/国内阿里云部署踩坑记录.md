# WeKnora 国内阿里云 Linux 3 部署踩坑记录

> 环境：Alibaba Cloud Linux 3.2104（底层 CentOS）、Docker 26.x、已有 PostgreSQL / Redis / OSS
> 目标：`docker compose build` 本地构建全部镜像（app + frontend + docreader）

---

## 一、总体策略调整

| 初始想法 | 实际正确做法 |
|-----------|-------------|
| `docker compose pull` 拉预编译镜像 | 放弃。`wechatopenai/weknora-*` 在 Docker Hub 不存在或极冷门，阿里云加速器回源超时 |
| 直接用原始 Dockerfile 构建 | 三套 Dockerfile 都需要针对国内网络环境修改（apt/pip/go proxy/npm 镜像） |

**核心原则：本地构建 + 全部走国内镜像源。**

---

## 二、Docker 镜像加速器问题

**故障**：`docker pull` 取精确 tag（如 `python:3.10.18-bookworm`）返回 500 或 content size zero

**原因**：
- 阿里云个人加速器对冷门/精确版本 tag 无缓存，回源 Docker Hub 不稳定
- 部分镜像 manifest 本地缓存损坏，表现为 `content size of zero`

**解决**：
1. **避免精确版本 tag**，改用滚动 tag：`python:3.10-slim` 替代 `python:3.10.18-bookworm`
2. **精准清理坏掉的镜像，不清 BuildKit 构建缓存**（否则 468MB 的包要重下）：
   ```bash
   docker rmi golang:1.24-bookworm 2>/dev/null    # 只删坏的
   docker pull golang:1.24-bookworm                 # 单独重拉
   ```
3. **加速器也拉不到时，从国内镜像站直接拉 + 打本地 tag**：
   ```bash
   docker pull docker.xuanyuan.me/library/golang:1.24-bookworm
   docker tag docker.xuanyuan.me/library/golang:1.24-bookworm golang:1.24-bookworm
   ```
   - 可用镜像站优先级：`docker.xuanyuan.me`（青云） > `docker.m.daocloud.io`（DaoCloud） > `docker.mirrors.ustc.edu.cn`（中科大，部分 DNS 不通）

## 三、docreader（Python）构建

### 3.1 Debian APT 源路径错误
**故障**：`sed: can't read /etc/apt/sources.list.d/debian.sources`

**原因**：原 Dockerfile 的 sed 路径适配 Debian 12 (Bookworm)，但 `python:3.10-slim` 基于 Debian 11 (Bullseye)，源文件在 `/etc/apt/sources.list`

**解决**：修改 Dockerfile 两处 sed 目标为 `/etc/apt/sources.list`

### 3.2 APT 下载 200+ 包极慢
**原因**：`apt-get install` 直连 `deb.debian.org`，国内带宽受限

**解决**：Dockerfile 预留了 `APT_MIRROR` 参数，构建时传入：
```bash
docker compose build --build-arg APT_MIRROR=https://mirrors.aliyun.com
```

### 3.3 APT 个别包超时
**故障**：`Connection timed out [IP: 202.104.186.222 443]` ，已下载 581MB 但最后一个包失败

**解决**：直接重试，BuildKit 缓存会复用已下载的层，只补下失败的文件

### 3.4 pip 不支持 `--break-system-packages`
**故障**：`no such option: --break-system-packages`

**原因**：`python:3.10-slim` 自带的 pip 版本过旧

**解决**：先升级 pip 再装 uv：
```dockerfile
RUN pip install --upgrade pip setuptools wheel && \
    pip install uv
```
（注：docreader 用的是 `python -m uv sync`，实际上 pip 只用来装 uv 本身，可去掉 `--break-system-packages`）

### 3.5 pip IncompleteRead 网络错误
**故障**：`IncompleteRead(20374080 bytes read, 4265579 more expected)`

**解决**：pip 和 uv 都配置阿里云 PyPI 镜像 + 超时重试：
```dockerfile
ENV UV_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/
RUN pip config set global.index-url https://mirrors.aliyun.com/pypi/simple/ && \
    pip config set global.trusted-host mirrors.aliyun.com && \
    pip install --upgrade pip setuptools wheel --default-timeout=100 --retries 5 && \
    pip install uv --default-timeout=100 --retries 5
```

### 3.6 uv 报 Python 版本不匹配
**故障 1**：`No interpreter found for Python >=3.10.18`

**原因**：`pyproject.toml` 的 `requires-python = ">=3.10.18"`，但 `python:3.10-slim` 自带 Python 3.10.12，不满足；同时设置了 `UV_PYTHON_PREFERENCE=only-system` 禁止 uv 自动下载

**故障 2**：放开 `only-system` 后，uv 自动下载了 CPython 3.14，导致 `paddlepaddle` 报 `cp314` 平台不支持

**解决**：
1. 放宽 `pyproject.toml` 中 `requires-python = ">=3.10"`（去掉小版本限制）
2. 从 `pyproject.toml` 删除 `paddleocr` 和 `paddlepaddle` 依赖（Dockerfile 注释早已说弃用 OCR，文件未同步）
3. 去掉 `UV_PYTHON_PREFERENCE=only-system`，让 uv 自然使用系统 Python 3.10

### 3.7 `uv.lock` 文件不存在
**故障**：`COPY docreader/uv.lock ./` 报文件不存在

**解决**：Dockerfile 中去掉 `uv.lock` 的 COPY，`uv sync` 会自动生成

## 四、app（Go）构建

### 4.1 `go install` 超时
**故障**：`dial tcp 142.250.73.81:443: i/o timeout`

**原因**：Go 模块代理 `proxy.golang.org` 是 Google 服务

**解决**：Dockerfile.app 预留了 `GOPROXY_ARG` 参数：
```bash
docker compose build --build-arg GOPROXY_ARG=https://goproxy.cn,direct
```

### 4.2 GOPROXY_ARG 格式错误
**故障**：`parse "GOPROXY=https://goproxy.cn": first path segment in URL cannot contain colon`

**原因**：Dockerfile 里是 `ENV GOPROXY=${GOPROXY_ARG}`，参数只传值不要带 `GOPROXY=` 前缀

**正确**：`--build-arg GOPROXY_ARG=https://goproxy.cn,direct`

## 五、frontend（Node.js/pnpm）构建

### 5.1 pnpm 构建脚本审批机制（最终方案：降级 pnpm）

**故障**：`ERR_PNPM_IGNORED_BUILDS` — esbuild、vue-demi、@vue-office/pptx 的 build scripts 被阻止

**尝试过的无效方案**（逐一失败）：

| 方案 | 结果 |
|------|------|
| `package.json` 加 `pnpm.onlyBuiltDependencies` | 不生效 |
| `pnpm-workspace.yaml` 加 `onlyBuiltDependencies` | 不生效 |
| `pnpm config set onlyBuiltDependencies` | `ERR_PNPM_CONFIG_SET_UNSUPPORTED_YAML_CONFIG_KEY`（非全局 key） |
| `pnpm install --allow-build=包名` | `Unknown option: 'allow-build'`（该 flag 不存在） |
| `ENV CI=true` | 不生效 |

**最终方案**：**降级 pnpm 到 v9**，v9 没有构建脚本审批机制，白名单配置也不需要：
```dockerfile
RUN corepack enable && corepack prepare pnpm@9 --activate
RUN pnpm install
```

> 注意：不要复制 `pnpm-lock.yaml`（pnpm 11 的锁文件 pnpm 9 可能读不了），让 pnpm 9 重新生成

## 六、最终构建命令

```bash
docker compose build \
  --build-arg APT_MIRROR=https://mirrors.aliyun.com \
  --build-arg GOPROXY_ARG=https://goproxy.cn,direct
```

## 七、关键经验总结

1. **Docker 镜像加速器 ≠ 万能**：冷门 tag 回源常失败，用滚动 tag + 必要时手动从国内站拉取打 tag
2. **缓存精准清理**：只删坏镜像不删 BuildKit 构建缓存，避免 400MB+ 层重下
3. **所有包管理器都要配国内源**：apt → 阿里云、pip → 阿里云、go → goproxy.cn、pnpm 降级 v9 绕道
4. **构建参数格式**：`ARG` 只传值，Dockerfile 内部拼成完整环境变量
5. **工具版本陷阱**：pnpm 11 的安全机制在 CI/Docker 环境几乎无法绕过，降级大版本是最快方案
6. **pyproject.toml 与 Dockerfile 需同步**：注释说弃用的依赖要从配置文件中删除，否则 uv 解析时会报错
