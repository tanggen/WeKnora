# WeKnora 技术栈分析

## 一、总体架构

WeKnora 采用 **微服务 + 插件化** 架构，分为三大核心服务和一个前端应用：

```
┌─────────────┐    ┌─────────────┐    ┌──────────────┐
│   Frontend   │    │  Go App API │    │  DocReader   │
│  (Vue 3)     │───▶│  (Gin Web)  │───▶│  (Python     │
│  Nginx       │    │  端口 8080  │    │   gRPC)      │
│  端口 80     │    │             │    │  端口 50051   │
└─────────────┘    └─────┬───────┘    └──────────────┘
                         │
              ┌──────────┼──────────┐
              ▼          ▼          ▼
        ┌─────────┐ ┌───────┐ ┌─────────┐
        │PostgreSQL│ │ Redis │ │ 对象存储  │
        │(ParadeDB)│ │       │ │S3/OSS/  │
        │          │ │       │ │MinIO/COS│
        └─────────┘ └───────┘ └─────────┘
```

## 二、后端技术栈 (Go)

### 2.1 语言与框架

| 技术 | 版本 | 用途 |
|------|------|------|
| **Go** | 1.24.11 | 主编程语言 |
| **Gin** | v1.10 | HTTP Web 框架，路由、中间件 |
| **GORM** | v1.30 | ORM 框架，支持 PostgreSQL/SQLite/MySQL |
| **go-micro** | v2 系列 | 微服务框架基础设施 |

### 2.2 依赖注入

| 技术 | 说明 |
|------|------|
| **uber/dig** | DI 容器，管理所有 Service/Repository 的生命周期和依赖关系 |

容器定义位于 `internal/container/container.go`，通过 `dig` 的 `Provide`/`Invoke` 模式组装整个应用。

### 2.3 数据库与存储

| 技术 | 用途 |
|------|------|
| **PostgreSQL (ParadeDB)** | 主数据库 + 向量存储 + 全文搜索 |
| **pgvector/pgx** | PostgreSQL 向量扩展驱动 |
| **pg_search (ParadeDB)** | BM25 全文检索扩展 |
| **Redis** | 缓存、Asynq 任务队列、Session 状态、FAQ 导入进度 |
| **DuckDB** | 内嵌分析数据库（用于数据集评估） |
| **SQLite** | Lite 模式下的替代数据库 |

#### ParadeDB 说明

WeKnora **必须使用 ParadeDB** 而非标准 PostgreSQL，因为依赖两个专有扩展：
- `pgvector`：向量存储与 HNSW 索引（余弦相似度检索）
- `pg_search`：BM25 全文检索（倒排索引）

数据表使用 `halfvec` 半精度向量类型节省存储空间，通过 HNSW 索引加速向量检索。

### 2.4 检索引擎（多后端支持）

支持 6 种检索引擎，通过 Tenant 级别配置切换：

| 引擎 | 向量检索 | 关键词检索 | 说明 |
|------|----------|-----------|------|
| **PostgreSQL/ParadeDB** | ✅ pgvector | ✅ pg_search (BM25) | 默认引擎 |
| **Elasticsearch v7** | ✅ | ✅ | 企业级搜索引擎 |
| **Elasticsearch v8** | ✅ | ✅ | 最新版本 |
| **Qdrant** | ✅ | ❌ | 高性能向量数据库 |
| **Milvus** | ✅ | ❌ | 分布式向量数据库 |
| **Weaviate** | ✅ | ❌ | 向量 + 对象混合数据库 |
| **SQLite** | ✅ (通过扩展) | ❌ | Lite 模式使用 |

代码参见 `internal/types/tenant.go` 中 `retrieverEngineMapping`。

### 2.5 对象存储引擎

支持 8 种存储后端，通过 Tenant 或 KnowledgeBase 级别配置切换：

| 引擎 | SDK |
|------|-----|
| **Local** | 本地文件系统 |
| **MinIO** | minio-go v7 |
| **AWS S3** | aws-sdk-go-v2 |
| **阿里云 OSS** | aliyun-oss-go-sdk |
| **腾讯云 COS** | cos-go-sdk-v5 |
| **火山引擎 TOS** | volcengine-go-sdk |
| **金山云 KS3** | ks3-go-sdk |

### 2.6 异步任务

| 技术 | 用途 |
|------|------|
| **Asynq** (hibiken/asynq) | 基于 Redis 的分布式任务队列 |
| **Redis** | 任务队列后端 |

文档处理（解析、分块、嵌入、索引）全部通过 Asynq 异步执行，避免阻塞 HTTP 请求。

### 2.7 LLM / AI 集成

| 技术 | 用途 |
|------|------|
| **OpenAI Go SDK** | ChatGPT 兼容 API 调用 |
| **Ollama SDK** | 本地模型调用 |
| **go-openai** | 通用 OpenAI 兼容客户端 |

支持的 LLM 能力：
- Chat Completion（流式对话 + 思考链）
- Embedding 生成
- Rerank（重排序）

### 2.8 可观测性

| 技术 | 用途 |
|------|------|
| **OpenTelemetry** | 分布式链路追踪 |
| **Langfuse** | LLM 调用追踪与监控 |
| **go-logger** | 结构化日志 |

### 2.9 其他关键依赖

| 技术 | 用途 |
|------|------|
| **golang-jwt/jwt v5** | JWT Token 生成与验证 |
| **gojieba** | 中文分词（关键词提取） |
| **goquery** | HTML 解析（网络搜索） |
| **pdfcpu** | PDF 处理 |
| **gRPC** | 与 Python DocReader 通信 |
| **Swagger** | API 文档自动生成 |
| **Wails** | 桌面应用框架（可选） |
| **playwright-go** | 浏览器自动化（网页抓取） |

### 2.10 项目结构

```
internal/
├── agent/          # Agent 智能体引擎（插件化管道）
├── application/
│   ├── repository/ # 数据访问层
│   └── service/    # 业务逻辑层
│       ├── chat_pipeline/  # 对话管道插件（搜索、合并、LLM）
│       ├── file/           # 文件存储服务
│       └── retriever/      # 检索引擎实现
├── common/         # 通用工具
├── config/         # 配置管理
├── container/      # DI 容器
├── database/       # 数据库迁移
├── handler/        # HTTP 请求处理器（Controller）
├── im/             # IM 集成（微信/飞书/钉钉/Slack）
├── infrastructure/ # 基础设施层（分块器、文档解析器）
├── middleware/     # Gin 中间件（认证、限流、追踪）
├── models/         # LLM 模型适配器
├── mcp/            # MCP 协议客户端
├── router/         # 路由注册
├── searchutil/     # 搜索工具函数
├── types/          # 领域模型与接口定义
└── utils/          # 工具函数
```

## 四、文档解析服务 (Python)

### 4.1 技术栈

| 技术 | 版本要求 | 用途 |
|------|---------|------|
| **Python** | 3.10+ | 文档解析服务语言 |
| **gRPC** (grpcio) | - | 服务通信协议 |
| **uv** | - | Python 包管理器 |

### 4.2 文档解析能力

| 文件格式 | 解析库 | 说明 |
|---------|--------|------|
| **DOCX** | python-docx + markitdown | 支持标题层级、表格、图片提取 |
| **PDF** | pdfplumber + pypdf + markitdown | 支持文字提取、表格识别 |
| **Excel** | markitdown + openpyxl | 支持 xls/xlsx |
| **PPT** | markitdown | 支持 pptx |
| **Markdown** | 原生解析 | 保持格式结构 |
| **图片** | pillow + OCR | 支持 OCR 文字识别 |
| **网页** | BeautifulSoup4 + trafilatura + playwright | 网页内容抓取 |
| **CSV** | markitdown | CSV 数据解析 |

### 4.3 高级能力

| 能力 | 技术 |
|------|------|
| **OCR 识别** | 可插拔 OCR 后端（MinerU 等） |
| **图片描述** | VLM 多模态模型（OpenAI/Ollama） |
| **PDF 高质量解析** | MinerU 集成（可选） |
| **浏览器渲染** | Playwright（JS 动态页面） |

### 4.4 主要 Python 依赖

## 五、基础设施

### 5.1 容器化

| 技术 | 用途 |
|------|------|
| **Docker** | 容器运行时 |
| **Docker Compose** | 多服务编排 |
| **Supervisor** | 容器内进程管理 |

Docker Compose 定义三个服务：
- `frontend`：Nginx + Vue 静态文件
- `app`：Go 后端 API
- `docreader`：Python gRPC 文档解析

### 5.2 可选组件

| 组件 | 用途 |
|------|------|
| **Neo4j** | 知识图谱存储（可选） |
| **Jaeger** | 分布式追踪收集（可选） |
| **Elasticsearch** | 替代检索后端（可选） |
| **Qdrant / Milvus / Weaviate** | 替代向量数据库（可选） |
| **MinIO** | 本地对象存储（替代云存储） |

## 六、支持的集成

- **IM 平台**：企业微信、飞书、钉钉、Slack、WeChat
- **OIDC 认证**：支持 OpenID Connect 单点登录
- **MCP 服务**：支持 Model Context Protocol 工具调用
- **Web 搜索**：支持可配置的网络搜索引擎
- **数据源导入**：Notion、语雀等第三方数据源
- **桌面应用**：通过 Wails 封装（开发中）
- **微信小程序**：miniprogram 目录下的微信小程序客户端
