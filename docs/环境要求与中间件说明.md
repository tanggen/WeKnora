# WeKnora 环境要求与中间件说明

> 本文档基于 WeKnora v0.5.1 整理，涵盖项目运行所需的全部中间件、外部服务及配置说明。

---

## 一、概述

WeKnora 采用模块化架构，各组件均可插拔替换。根据部署场景不同，分为两套环境需求：

| 部署模式 | 适用场景 | 所需中间件 |
|---------|---------|-----------|
| **Lite 模式** | 本地单机、快速体验、开发调试 | SQLite（内置）、内存流管理、本地存储、Ollama |
| **完整模式** | 生产环境、团队协作、多租户 | PostgreSQL、Redis、对象存储、向量数据库、可选可观测性栈 |

---

## 二、必需中间件（最小部署）

无论哪种部署模式，以下组件均为必需：

### 2.1 主数据库

| 项目 | 说明 |
|------|------|
| **Lite 模式** | SQLite（文件型，零配置） |
| **完整模式** | PostgreSQL（推荐 ParadeDB v0.22.2-pg17，内置 pgvector + BM25） |
| **可选** | MySQL |

**PostgreSQL 配置要点：**
- 版本：PostgreSQL 17（ParadeDB 镜像已内置 pgvector、pg_search）
- 持久化：需挂载数据卷
- 健康检查：`pg_isready` 命令

### 2.2 文档解析服务（Docreader）

| 项目 | 说明 |
|------|------|
| **镜像** | `wechatopenai/weknora-docreader` |
| **协议** | gRPC（默认端口 50051）|
| **职责** | PDF、Word、Excel、PPT、图片等 10+ 格式解析 |
| **依赖** | Python 环境，独立容器运行 |

### 2.3 缓存 / 流管理 / 任务队列（Redis）

| 项目 | 说明 |
|------|------|
| **Lite 模式** | 内存（`STREAM_MANAGER_TYPE=memory`） |
| **完整模式** | Redis 7.0+（`STREAM_MANAGER_TYPE=redis`） |
| **职责** | SSE 流状态管理、asynq 异步任务队列、限流、多实例协调 |

**Redis 配置要点：**
- 建议开启 AOF 持久化（`appendonly yes`）
- 建议设置密码（`requirepass`）
- Langfuse 自建时建议使用独立 DB 号（如 DB 1）避免冲突

---

## 三、可选中间件

### 3.1 向量数据库（五选一或多）

WeKnora 支持多种向量数据库，按需选择：

| 向量数据库 | Docker 镜像 | 默认端口 | 特点 |
|-----------|------------|---------|------|
| **PostgreSQL + pgvector** | `paradedb/paradedb:v0.22.2-pg17` | 5432 | 与主库合一，最简单 |
| **Elasticsearch** | 需外部部署 | 9200 | 适合已有 ES 集群 |
| **Milvus** | `milvusdb/milvus:v2.6.11` | 19530 / 9091 | 高性能，支持大规模 |
| **Weaviate** | `semitechnologies/weaviate:1.28.4` | 8080 / 50051 | 模块化向量引擎 |
| **Qdrant** | `qdrant/qdrant:v1.16.2` | 6333 / 6334 | 轻量高效，Rust 实现 |

> **建议**：小规模部署直接用 ParadeDB（PostgreSQL + pgvector）；大规模场景可选 Milvus 或 Qdrant。

### 3.2 对象存储（五选一）

| 存储类型 | 适用场景 |
|---------|---------|
| **Local** | 单机部署，文件存在本地磁盘 |
| **MinIO** | 私有化 S3 兼容存储 |
| **AWS S3** | 公有云部署 |
| **阿里云 OSS** | 阿里云环境 |
| **腾讯云 COS** | 腾讯云环境 |
| **火山引擎 TOS** | 字节云环境 |

**MinIO 配置要点：**
- 镜像：`minio/minio`
- 端口：9000（API）、9001（控制台）
- 命令：`server --console-address ":9001" /data`

### 3.3 知识图谱（Neo4j）

| 项目 | 说明 |
|------|------|
| **镜像** | `neo4j:2025.10.1` |
| **端口** | 7474（HTTP）、7687（Bolt）|
| **开关** | `ENABLE_GRAPH_RAG=true` + `NEO4J_ENABLE=true` |
| **插件** | APOC（已预配置） |
| **注意** | 构建阶段需调用大模型提取实体关系，耗时较长 |

### 3.4 可观测性栈（Langfuse）

支持两种接入方式：

**方案 A：Langfuse Cloud（推荐）**
- 无需额外容器，只需配置 `LANGFUSE_PUBLIC_KEY` + `LANGFUSE_SECRET_KEY`

**方案 B：自建 Langfuse（内网/局域网）**

启动命令：`docker compose --profile langfuse up -d`

| 组件 | 镜像 | 职责 |
|------|------|------|
| `langfuse-web` | `langfuse/langfuse:3` | Web UI（默认端口 3000）|
| `langfuse-worker` | `langfuse/langfuse-worker:3` | 后台异步处理 |
| `langfuse-clickhouse` | `clickhouse/clickhouse-server:24.8` | OLAP 分析数据库 |
| `langfuse-minio` | `minio/minio` | 事件/媒体 S3 存储（端口 9100/9101）|
| `langfuse-db-init` | `paradedb/paradedb` | 一次性初始化，在 PostgreSQL 中创建 `langfuse` 库 |

**复用策略**：
- PostgreSQL：复用 WeKnora 主库，创建独立 `langfuse` 数据库
- Redis：复用 WeKnora Redis，使用独立 DB 号（默认 DB 1）

### 3.5 链路追踪（Jaeger）

| 项目 | 说明 |
|------|------|
| **镜像** | `jaegertracing/all-in-one:1.76.0` |
| **Web UI** | http://localhost:16686 |
| **OTLP gRPC** | 端口 4317 |
| **配置** | `OTEL_EXPORTER_OTLP_ENDPOINT=jaeger:4317` |

### 3.6 OIDC 认证（Dex）

| 项目 | 说明 |
|------|------|
| **镜像** | `dexidp/dex:latest` |
| **端口** | 5556 |
| **配置** | `misc/dex-config.yaml` |
| **开关** | `OIDC_AUTH_ENABLE=true` |

### 3.7 LLM 服务

WeKnora 本身不内置 LLM，需连接外部服务：

| LLM 提供方 | 配置方式 |
|-----------|---------|
| **Ollama（本地）** | `OLLAMA_BASE_URL=http://host.docker.internal:11434` |
| **OpenAI / Azure** | 在 UI 或数据库中配置 API Key 和 Base URL |
| **DeepSeek / 通义千问 / 智谱 等** | 同上，共支持 20+ 厂商 |

## 四、端口占用总览

### 4.1 默认端口列表

| 服务 | 容器内端口 | 宿主机映射端口 | 说明 |
|------|-----------|--------------|------|
| Frontend (Nginx) | 80 | 80 | Web UI |
| App (Backend) | 8080 | 8080 | RESTful API |
| Docreader (gRPC) | 50051 | 50051 | 文档解析 |
| PostgreSQL | 5432 | -（不暴露） | 主数据库 |
| Redis | 6379 | -（不暴露） | 缓存/队列 |
| MinIO API | 9000 | 9000 | S3 API |
| MinIO Console | 9001 | 9001 | 管理控制台 |
| Neo4j HTTP | 7474 | 7474 | 图数据库浏览器 |
| Neo4j Bolt | 7687 | 7687 | 图数据库协议 |
| Qdrant HTTP | 6333 | 6333 | 向量数据库 REST |
| Qdrant gRPC | 6334 | 6334 | 向量数据库 gRPC |
| Milvus | 19530 | 19530 | 向量数据库 |
| Milvus 管理 | 9091 | 9091 | 健康检查/监控 |
| Weaviate HTTP | 8080 | 9035 | 向量数据库（避免与 App 冲突）|
| Weaviate gRPC | 50051 | 50052 | 向量数据库 gRPC（避免与 Docreader 冲突）|
| Jaeger UI | 16686 | 16686 | 链路追踪 UI |
| Jaeger OTLP gRPC | 4317 | 4317 | OpenTelemetry 接收器 |
| Langfuse Web | 3000 | 3000 | 可观测性 UI |

| Dex (OIDC) | 5556 | 5556 | 认证服务 |

### 4.2 端口冲突提示

- **Weaviate HTTP** 映射到宿主机的 **9035**（而非 8080），避免与 App 冲突
- **Weaviate gRPC** 映射到宿主机的 **50052**（而非 50051），避免与 Docreader 冲突
- **Langfuse MinIO** 使用 **9100/9101**，避免与主 MinIO 的 9000/9001 冲突

## 五、核心环境变量说明

|--------|--------|------|
| `WEKNORA_VERSION` | `latest` | 镜像版本标签 |
| `GIN_MODE` | `release` | `debug`（开发）/ `release`（生产，禁用 Swagger）|
| `LOG_LEVEL` | `debug` | 日志级别：debug / info / warn / error / fatal |
| `TZ` | `Asia/Shanghai` | 系统时区 |
| `WEKNORA_LANGUAGE` | `zh-CN` | 系统默认语言（BCP-47 格式）|
| `DISABLE_REGISTRATION` | `false` | 是否禁止新用户注册（生产建议 `true`）|

### 5.2 数据库配置

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| `DB_DRIVER` | `postgres` | 数据库类型：`postgres` / `mysql` / `sqlite`（Lite）|
| `DB_HOST` | `localhost` | 数据库地址 |
| `DB_PORT` | `5432` | 数据库端口 |
| `DB_USER` | `postgres` | 数据库用户名 |
| `DB_PASSWORD` | - | 数据库密码 |
| `DB_NAME` | `WeKnora` | 数据库名 |
| `DB_PATH` | `./data/weknora.db` | Lite 模式下 SQLite 文件路径 |

### 5.3 Redis 配置

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| `REDIS_ADDR` | `redis:6379` | Redis 地址（Docker 内）|
| `REDIS_PASSWORD` | - | Redis 密码 |
| `REDIS_DB` | `0` | Redis 数据库索引 |
| `REDIS_PREFIX` | `stream:` | Key 前缀 |

### 5.4 向量存储配置

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| `RETRIEVE_DRIVER` | `postgres` | 向量存储类型：`postgres` / `elasticsearch_v7` / `elasticsearch_v8` / `qdrant` / `milvus` / `weaviate` / `sqlite`（Lite）|

**各向量库特有配置**（仅在使用时填写）：

- **Elasticsearch**：`ELASTICSEARCH_ADDR`、`ELASTICSEARCH_USERNAME`、`ELASTICSEARCH_PASSWORD`、`ELASTICSEARCH_INDEX`

### 5.5 对象存储配置

| 变量名 | 默认值 | 说明 |

## 六、部署模式对比

### 6.1 Lite 模式（最小资源）

```bash
cp .env.lite.example .env.lite
# 按需修改后启动
```

**特点**：
- 数据库：SQLite（文件型）
- 向量检索：sqlite-vec（FTS5 + 向量）
- 流管理：内存（无 Redis）
- 存储：本地磁盘
- 沙箱：`disabled`
- 知识图谱：`false`
- **无 Docker Compose 依赖**，适合本地二进制/桌面端运行

### 6.2 完整模式（Docker Compose）

```bash
cp .env.example .env
# 按需修改后启动
docker compose up -d
```

**特点**：
- 数据库：PostgreSQL（ParadeDB）
- 向量检索：pgvector 或其他独立向量库
- 流管理：Redis
- 存储：可接 MinIO/S3/OSS 等
- 可选组件通过 `--profile` 按需启用

### 6.3 Profile 组合

| Profile | 启用组件 |
|---------|---------|
| （默认，无） | frontend + app + docreader + postgres + redis |
| `full` | 全部组件（包括可选中间件）|
| `neo4j` | Neo4j 知识图谱 |
| `minio` | MinIO 对象存储 |
| `langfuse` | Langfuse 可观测性栈 |
| `qdrant` | Qdrant 向量数据库 |
| `milvus` | Milvus 向量数据库 |
| `weaviate` | Weaviate 向量数据库 |
| `jaeger` | Jaeger 链路追踪 |
| `dex` | Dex OIDC 认证 |

**组合示例**：

```bash
# 核心 + 知识图谱 + MinIO
docker compose --profile neo4j --profile minio up -d

# 核心 + 可观测性
docker compose --profile langfuse up -d

# 全部组件
docker compose --profile full up -d
```

## 七、资源需求估算

### 7.1 最小部署（核心服务）

| 组件 | CPU | 内存 | 存储 |
|------|-----|------|------|
| App | 0.5 核 | 512 MB | - |
| Frontend (Nginx) | 0.1 核 | 64 MB | - |
| Docreader | 0.5 核 | 1 GB | - |
| PostgreSQL | 0.5 核 | 1 GB | 10 GB+ |
| Redis | 0.1 核 | 256 MB | - |
| **合计** | **~1.7 核** | **~2.8 GB** | **10 GB+** |

### 7.2 完整部署（含可选组件）

| 组件 | CPU | 内存 | 存储 |
|------|-----|------|------|
| 核心服务 | 1.7 核 | 2.8 GB | 10 GB |
| Neo4j | 1 核 | 2 GB | 20 GB+ |
| MinIO | 0.5 核 | 512 MB | 50 GB+ |
| Qdrant / Milvus / Weaviate | 0.5~1 核 | 1~2 GB | 10 GB+ |
| Langfuse 栈 | 1 核 | 2 GB | 20 GB+ |
| Jaeger | 0.5 核 | 512 MB | 5 GB+ |
| **合计** | **~5~7 核** | **~10~12 GB** | **100 GB+** |

> 以上为粗略估算，实际资源需求取决于数据量、并发量和模型调用频率。

## 八、配置检查清单

部署前请确认以下配置：

- [ ] `.env` 文件已创建并正确填写
- [ ] 数据库密码已修改（避免使用默认值）
- [ ] `JWT_SECRET` 已设置为随机字符串
- [ ] `SYSTEM_AES_KEY` / `TENANT_AES_KEY` 已设置为 32 字节密钥
- [ ] 向量数据库选型已确定并配置正确
- [ ] 对象存储选型已确定并配置正确
- [ ] `OLLAMA_BASE_URL` 或云厂商 API Key 已配置
- [ ] `APP_EXTERNAL_URL` 已配置（如使用 IM 渠道）
- [ ] 防火墙/安全组已开放必要端口
- [ ] 生产环境：`DISABLE_REGISTRATION=true`
- [ ] 生产环境：Langfuse 安全字段已重新生成（`SALT`、`ENCRYPTION_KEY`、`NEXTAUTH_SECRET`）
