# 基于现有中间件的 WeKnora 部署方案

> 针对已有 **MySQL**、**Redis 6.0.6**、**阿里云 OSS** 的环境，梳理项目实际兼容性、可行方案及配置示例。

---

## 一、兼容性评估

| 已有中间件 | 项目兼容性 | 说明 |
|-----------|-----------|------|
| **MySQL** | ⚠️ **需改造** | 业务代码中有 MySQL 方言处理（JSON 查询、批量插入、死锁重试），但 `go.mod` 缺少 `gorm.io/driver/mysql`，且数据库初始化（`container.go`）未实现 MySQL 分支 |
| **Redis 6.0.6** | ✅ **可直接使用** | `go-redis/v9` 和 `asynq` 均兼容 Redis 6.x，流（Streams）和 ACL 功能可用 |
| **阿里云 OSS** | ✅ **原生支持** | 项目内置腾讯云 COS、火山引擎 TOS、阿里云 OSS、AWS S3 适配 |

---

## 二、MySQL 现状详解

### 2.1 已具备的 MySQL 支持

代码中多处处理了 MySQL 方言：

- **JSON 查询**：`JSON_EXTRACT`、`JSON_CONTAINS` 用于 FAQ 去重检索
- **批量插入**：处理了 `ON DUPLICATE KEY UPDATE` 的占位符限制（Error 1390）
- **死锁重试**：检测到 MySQL Error 1213 时自动重试
- **初始化脚本**：`migrations/mysql/00-init-db.sql` 已包含完整建表语句

### 2.2 缺失的部分

| 缺失项 | 位置 | 影响 |
|--------|------|------|
| GORM MySQL 驱动 | `go.mod` | 无法编译连接 MySQL |
| 数据库初始化逻辑 | `internal/container/container.go:394~456` | `DB_DRIVER` switch 只有 `postgres` / `sqlite`，无 `mysql` |
| 迁移 DSN 格式 | `internal/container/container.go` | `golang-migrate` 未配置 MySQL 迁移源 |

### 2.3 结论

> **当前版本（v0.5.1）无法直接将 MySQL 作为主数据库使用。**
>
> 若坚持使用 MySQL，需要自行修改源码添加支持（见下文【附录：MySQL 适配改造】）。

**建议**：主数据库仍使用项目推荐的 **PostgreSQL（ParadeDB）** 或 **SQLite**（Lite 模式），Redis 和 OSS 直接使用现有服务。

## 三、推荐部署方案

### 方案 A：最小改造（推荐）

利用你现有的 **Redis 6.0.6** 和 **OSS**，主数据库使用 PostgreSQL。

```yaml
# docker-compose.yml 中需要启动的服务（精简版）
# 注释掉或移除以下服务：
#   - redis（使用外部 Redis）
#   - minio（使用阿里云 OSS）
# 保留以下服务：
#   - frontend
#   - app
#   - docreader
#   - postgres
```

**`.env` 关键配置：**

```bash
# ========== 数据库（使用 Docker 内 PostgreSQL）==========
DB_DRIVER=postgres
DB_HOST=postgres
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=your_postgres_password
DB_NAME=WeKnora

# ========== Redis（使用你现有的 Redis 6.0.6）==========
# 将 REDIS_ADDR 指向你的 Redis 实例
# 如果是宿主机上的 Redis：host.docker.internal:6379
# 如果是局域网内其他机器：192.168.x.x:6379
REDIS_ADDR=your_redis_host:6379
REDIS_PASSWORD=your_redis_password
REDIS_DB=0
REDIS_PREFIX=stream:

# 流管理后端
STREAM_MANAGER_TYPE=redis

# ========== 对象存储（使用阿里云 OSS）==========
STORAGE_TYPE=cos          # 项目将阿里云 OSS 标记为 cos（历史原因）
COS_SECRET_ID=your_oss_access_key_id
COS_SECRET_KEY=your_oss_access_key_secret
COS_REGION=oss-cn-hangzhou        # 根据实际区域修改，如 oss-cn-beijing
COS_BUCKET_NAME=your_bucket_name
COS_PATH_PREFIX=weknora/
COS_ENABLE_OLD_DOMAIN=true

# 可选：限制用户只能使用 OSS
STORAGE_ALLOW_LIST=cos

# ========== 向量存储 ==========
# 如果 PostgreSQL 使用 ParadeDB 镜像，可直接用 pgvector
RETRIEVE_DRIVER=postgres

# 如果你有独立的向量数据库（如 ES/Milvus），可切换
# RETRIEVE_DRIVER=elasticsearch_v8

# ========== 文档解析 ==========
DOCREADER_ADDR=docreader:50051
DOCREADER_TRANSPORT=grpc

# ========== 安全配置（生产务必修改）==========
JWT_SECRET=your_random_jwt_secret
TENANT_AES_KEY=your_32_byte_tenant_key!!
SYSTEM_AES_KEY=your_32_byte_system_key!!

# ========== 其他 ==========
GIN_MODE=release
TZ=Asia/Shanghai
WEKNORA_LANGUAGE=zh-CN
DISABLE_REGISTRATION=false
OLLAMA_BASE_URL=http://host.docker.internal:11434
CONCURRENCY_POOL_SIZE=5
```

**docker-compose 调整（移除 redis/minio）：**

在 `docker-compose.yml` 中：

1. 删除 `redis` 服务定义
2. 删除 `minio` 服务定义（如果使用 OSS）
3. 在 `app` 服务的 `depends_on` 中移除 `redis`
4. 确保 `app` 容器能访问外部 Redis（网络连通性）

### 方案 B：Lite 模式（零外部依赖，除 Redis/OSS）

如果你希望进一步精简，甚至不需要 PostgreSQL：

```bash
# .env.lite
DB_DRIVER=sqlite
DB_PATH=./data/weknora.db
RETRIEVE_DRIVER=sqlite
STORAGE_TYPE=local        # 或改为 cos 使用 OSS
STREAM_MANAGER_TYPE=redis  # 使用你现有的 Redis

REDIS_ADDR=your_redis_host:6379
REDIS_PASSWORD=your_redis_password

# OSS 配置同上
COS_SECRET_ID=xxx
COS_SECRET_KEY=xxx
COS_REGION=oss-cn-hangzhou
COS_BUCKET_NAME=your_bucket
```

> Lite 模式适合个人使用或开发调试，SQLite 的并发性能和数据容量有限，**不建议生产环境使用**。

## 四、Redis 6.0.6 使用注意事项

### 4.1 功能兼容性

| 功能 | Redis 6.0 支持 | WeKnora 使用场景 |
|------|---------------|-----------------|
| Streams | ✅ | asynq 任务队列 |
| ACL | ✅（基础） | 用户名密码认证 |
| RESP3 | ❌（6.0 为 RESP2） | go-redis 自动适配 |
| Functions | ❌（7.0+） | 未使用 |

**结论**：Redis 6.0.6 功能上完全满足 WeKnora 需求，无需升级。

### 4.2 配置建议

```bash
# redis.conf 关键配置
appendonly yes                    # 开启 AOF 持久化
requirepass your_strong_password  # 设置密码
maxmemory 2gb                     # 根据实际内存调整
maxmemory-policy allkeys-lru      # 内存满时淘汰策略
```

### 4.3 连接验证

```bash
# 从宿主机测试 Redis 连接
redis-cli -h your_redis_host -p 6379 -a your_password ping

# 从 Docker 容器内测试（启动后进入 app 容器）
docker exec -it WeKnora-app sh
apk add redis
redis-cli -h your_redis_host -p 6379 -a your_password ping
```

## 五、阿里云 OSS 配置详解

### 5.1 获取凭证

登录 [阿里云 OSS 控制台](https://oss.console.aliyun.com/)：

1. 创建/选择 Bucket
2. 记录 **Endpoint**（如 `oss-cn-hangzhou.aliyuncs.com`）
3. 在 RAM 访问控制中创建用户，授予 `AliyunOSSFullAccess` 权限
4. 创建 AccessKey，记录 **AccessKey ID** 和 **AccessKey Secret**

### 5.2 WeKnora 配置映射

| WeKnora 变量 | 阿里云 OSS 对应项 |
|-------------|------------------|
| `COS_SECRET_ID` | AccessKey ID |
| `COS_SECRET_KEY` | AccessKey Secret |
| `COS_REGION` | Endpoint 中的区域，如 `oss-cn-hangzhou` |
| `COS_BUCKET_NAME` | Bucket 名称 |
| `COS_PATH_PREFIX` | 文件存储前缀，如 `weknora/files/` |

### 5.3 注意事项

- `COS_ENABLE_OLD_DOMAIN=true` 使用旧版域名格式（`bucket.oss-region.aliyuncs.com`）
- 如果 Bucket 设置为私有，确保 WeKnora 的签名 URL 生成逻辑正常工作
- 跨域访问：若前端直接访问 OSS，需在 Bucket 中配置 CORS 规则

## 六、附录：MySQL 适配改造（如需使用）

如果你坚持要用 MySQL 作为主数据库，需要以下改造：

### 步骤 1：添加依赖

```bash
go get -u gorm.io/driver/mysql
go mod tidy
```

### 步骤 2：修改数据库初始化

在 `internal/container/container.go` 的 `DB_DRIVER` switch 中添加：

```go
case "mysql":
    gormDSN := fmt.Sprintf(
        "%s:%s@tcp(%s:%s)/%s?charset=utf8mb4&parseTime=True&loc=Local",
        os.Getenv("DB_USER"),
        os.Getenv("DB_PASSWORD"),
        os.Getenv("DB_HOST"),
        os.Getenv("DB_PORT"),
        os.Getenv("DB_NAME"),
    )
    dialector = mysql.Open(gormDSN)
    migrateDSN = fmt.Sprintf(
        "mysql://%s:%s@tcp(%s:%s)/%s",
        os.Getenv("DB_USER"),
        url.QueryEscape(os.Getenv("DB_PASSWORD")),
        os.Getenv("DB_HOST"),
        os.Getenv("DB_PORT"),
        os.Getenv("DB_NAME"),
    )
```

### 步骤 3：处理迁移

- MySQL 的 `golang-migrate` DSN 格式与 PostgreSQL 不同，需确保迁移文件兼容
- `migrations/mysql/00-init-db.sql` 可直接使用，但后续版本化迁移需检查 MySQL 兼容性

### 步骤 4：向量存储

MySQL 不支持向量检索，必须额外配置独立向量数据库（Elasticsearch / Milvus / Qdrant / Weaviate）：

```bash
RETRIEVE_DRIVER=elasticsearch_v8  # 或 milvus / qdrant / weaviate
```

> **警告**：MySQL 适配未经项目官方测试，可能遇到未覆盖的方言差异问题。建议优先使用 PostgreSQL。

## 七、部署检查清单

- [ ] 确认 Redis 6.0.6 可从 WeKnora 服务器访问（网络/防火墙）
- [ ] 确认阿里云 OSS 的 AccessKey 拥有读写权限
- [ ] PostgreSQL 密码已修改，且与现有 MySQL 密码不同（避免混淆）
- [ ] `JWT_SECRET`、`TENANT_AES_KEY`、`SYSTEM_AES_KEY` 已设置为随机值
- [ ] `.env` 中的 `REDIS_ADDR` 指向正确的外部地址（非 `redis:6379`）
- [ ] 若使用本地 Ollama，确认宿主机已运行 `ollama serve`
- [ ] 若使用云厂商 LLM，在 WeKnora UI 中配置 API Key
- [ ] 生产环境：`DISABLE_REGISTRATION=true`
- [ ] docker-compose.yml 中已移除不需要的 `redis` / `minio` 服务
